# dsh-firstaid · 报错急救

> 贴一段报错，说出最可能的原因和**一步能做的事**。匹配不到就说不知道。

`dsh-firstaid` 是 DeepSeek Harness（DSH）的 Host-only 插件：一张确定性的「症状 → 原因 → 一步修复」规则表，加一个打分匹配器。不调模型、不扫机器、不联网，纯本地毫秒级返回。

---

## 30 秒看懂

**给谁**：DSH 装完/升级后起不来、或者用着用着报错，又不想发帖等回复的人。

**解决什么**：把「这大概是哪一类问题、现在能试什么」直接给你——不用先学会看日志。

**不解决什么**：不扫你的机器、不替你改配置、不联网；也不是「什么都能修」。它认得 32 类已知问题，认不出的会明说不知道，并告诉你该带什么去问。

**三步上手**

1. `dsh plugin --profile desktop add https://github.com/Daphne999/dsh-firstaid`，重启一次 DSH（bundle 插件首次要重启）
2. 出问题时把报错原文丢给它：`firstaid_error("你的报错原文")`
3. 想知道它认得哪些？`firstaid_list()`

## 为什么做这个

2026-11-17 在 DSH 官方讨论区（13,304 条）翻了两天的帖子，看到一个反复出现的场景：**首装就崩、报错一片红，然后发帖等人回**。

- `#13368`（18 条评论）：官网下的 0.2.2-rc.3，首次启动就「应用无法启动或已意外停止。fetch failed」
- `#13533` `#13532` `#13527`：同一天，同类
- `#10066`（14 条评论）/ `#8322`：Windows 上所有命令都死于 `0xC0000142`

但这些帖子里，**没有一条是"我装了个工具自己查出来了"**——大家要的是有人告诉他怎么修。所以这个插件不做体检面板（那是"你自己去看"），做**症状到解法**的直给。

## 它怎么工作

一句话：**规则表 + 匹配器**，没有模型，纯本地。

- `lib/rules.mjs`：32 条规则，每条是「症状信号 → 原因 → 可执行的修复 → 怎么确认」。信号是带权重的正则，权重越高说明这个字符串越不可能出现在别的地方。
- `lib/match.mjs`：把报错文本归一化后逐条打分。命中"硬信号"（比如 `0xC0000142`）直接收；否则要求命中权重占该条规则的 34% 以上，避免几个泛泛的词凑出一条假诊断。
- 匹配不到 → 返回"不猜"，并给出该带什么信息去问。

## 两个工具

| 工具 | 干什么 |
|---|---|
| `firstaid_error({ text, limit? })` | 贴报错，给最可能的原因 + 可执行步骤 + 怎么确认。`limit` 控制最多给几条候选（1-3，默认 2） |
| `firstaid_list()` | 列出能认出的全部 32 类问题，让你先判断自己的情况在不在覆盖范围内 |

## 规则的可信度分两档

每一条都标了来源，回答里也会写出来：

- **实测过**：我自己在这台机器上踩出来、并验证过修法（22 条）
- **社区报告**：来自公开讨论区/会话日志的重复故障，我没亲自复现（10 条）

不确定的**不写进去**。宁可少一条，也不要给一个看起来像答案的猜测——照着猜的步骤做，比不知道更糟。

## 2026-11-21 这一版加了什么

对 7 天内 17 个会话日志做了一次全量 `tool/result` 错误统计：**6875 次工具调用 / 152 次真实错误（2.21%）**，按归一化族聚合后，把跨 ≥2 个会话的前几名做成了规则：

| 错误族 | 次数 / 会话 | 新规则 |
|---|---|---|
| `file has not been read` | 30 / 7 | `fs-write-needs-read` |
| `file no longer exists` + `file changed since it was read` | 9 次 / 4 会话 + 8 次 / 2 会话 | `fs-stale-after-change` |
| `returned invalid output … oneOf` | 11 / 4 | `plugin-invalid-output-oneof` |
| `rejected checks — title is required` | 5 / 4 | `claimcheck-check-title-missing` |
| `version_conflict: stale version` | 6 / 2 | `taskboard-version-conflict` |
| `Select-Object: command not found`（bash 里跑 PowerShell 语法） | 本机实测 | `shell-dialect-mismatch` |

证据（条数、会话数、归一化方法）来自本机 7 天会话日志的一次性统计，不复述聊天内容、不含 token/路径；统计口径写在`CHANGELOG.md` 与本轮任务卡评论里。

## 验证记录

**2026-11-21**（宿主 node v24.19.0 / DSH runtime node v24.21.0）：

- `node --test --test-isolation=none test/*.test.mjs` — **4/4 pass**（规则结构、6 条新规则真实串匹配、unknown 不猜、工具输出无 null）
- `node test/smoke.mjs` — **5 组断言全过**：32 条规则结构完整；33 段真实报错全部对到正确条目；5 段无关文本返回"不知道"；版本/退出码/端口抽取；两个工具入参与输出形状
- 隔离 profile（独立 `DSH_HOME`，dsh-base + dsh-web-app + 本插件）真实启动：`dsh web` 打出 URL，stderr 无跳过/激活错误

**没测什么**：只在 Windows 上跑过；标"社区报告"的 10 条没有本地复现；没有真实用户拿它解决问题的验证。

## 边界与不做什么

- **只对已知症状有效**。规则表覆盖不到的新故障，它只会说不知道，不会编。
- **不做自动修复**。不给命令就替你执行——修复步骤需要你自己判断后执行。
- **不读机器状态**。不扫日志、不读配置、不查端口；你贴什么它看什么。
- **不是官方支持的诊断工具**。规则是我们自己和社区踩坑的总结，版本升级后可能过时；每条都带来源与验证时间。
